# 大厅配装完整复制 Mod 实施规范

状态：1.0.0 发布候选已完成当前功能组合验收，正在发布；历史记录按时间保留，最新结论见第 19 节。日期：2026-10-24。

## 1. 目标与范围

在 PC Steam《怪物猎人：崛起／曙光》中提供中文可视化面板，自动列出当前大厅玩家。用户选中一人、点击“完整复制”，生成独立装备并登记为本地原生配装。不要求打开原生查看装备界面，不要求拥有对应装备，不逐项确认。

包含武器、五件防具、护石、强化状态、武器傀异强化、防具完整炼化结果、全部普通及百龙装饰品、朱书与苍书替换技。虫棍猎虫及其他影响武器配置的附属数据必须在字段调查中核实；如需独立库存实例，应一并创建。花链作为当前装备配置的一部分纳入读取与登记调查，不默认为可忽略项。

不包含外观、染色、道具袋、快捷轮盘、随从、任务进度或解锁进度修改。遇到未解锁内容，不自动修改进度；若原生游戏拒绝使用，则中止并明确原因。默认不立即换装、不主动触发存盘，由游戏正常保存流程持久化；内存登记与重启持久化分别验证。

## 3. 体验与状态

入口为 REFramework 中的面板开关；面板独立显示成员列表、选中目标、复制按钮与就地结果。首版鼠标操作，快捷键只开关面板，不默认截获游戏手柄按钮。关闭面板后释放输入占用。

| 状态 | 可见内容和操作 |
|---|---|
| 初始／读档 | 等待角色与大厅数据，复制禁用 |
| 离线／无其他成员 | 显示暂无可复制玩家，可关闭面板 |
| 可用 | 成员名称、可取得的武器信息；选中后可复制 |
| 获取中 | 显示正在读取；禁止重复提交，不冻结游戏 |
| 校验／写入中 | 显示阶段；不允许开始第二个事务 |
| 成功 | 显示配装名称及槽位；只在回读一致后显示 |
| 失败 | 显示具体原因和重试入口；不得把失败当空列表 |
| 退出／切换角色 | 清空目标和失效引用；写入事务按已验证恢复机制处理 |

成员身份使用运行时可验证的会话标识，不能用名称或列表序号认定同一个人。长名称和中文不得重叠、乱码或造成控件 ID 冲突。面板采用可滚动区域，在 1280×720 与 1920×1080 验证。

## 4. 架构与数据契约

采用 REFramework Lua 与 ImGui，MVC：View 绘制与输入；Controller 协调选择和复制状态；Model 保存纯 Lua 快照、校验与事务状态。游戏适配器集中封装类型、字段和方法，不将托管对象引用混入持久快照。未经测量不引入原生 DLL。

快照包含来源身份、会话、武器类型、完整装备与附属配置、两套替换技、字段完整性及格式版本。任何必需字段缺失都禁止完整复制；不以总技能推算炼化，不用默认值补齐未知字段。

在目标版本中确认原生空槽判定、装备实例标识、库存数量、引用与保存语义，不能用空白名称判断空槽，也不能复制他人的库存下标作为自己的引用。

容量按本次实际需创建的对象数检查，不假设永远只有七个实例。装饰品按实际库存机制新增本次所需数量并校验上限，不挪用已有装备上的珠子。

选择配装槽位时从末尾向前找真实空槽。名称采用玩家名称加武器／序号，并按游戏实际长度规则处理。保持当前穿着不变；若原生登记必须临时穿戴，应先验证能完整恢复，否则不能使用该写入路线。

## 5. 写入与恢复

正常路径：获取一致快照 → 校验版本、字段、身份和容量 → 建立恢复记录 → 创建独立装备与所需物品 → 登记原生配装 → 回读逐项比较 → 标记成功。

所有游戏写入在已验证安全的回调阶段执行，不跨帧保留未经生命周期校验的原生指针。提交前检查角色与会话；复制期间抑制重复请求。源玩家装备变化时拒绝混合快照。

恢复记录涵盖本次新增槽位原状态、装饰品数量与目标配装原状态。失败只恢复本次拥有的修改。不得通过出售装备实现回滚，因为出售会产生金钱等副作用。回滚自身失败时立即禁止后续写入并明确报告，不能继续重试或宣称已恢复。

首次真实写入测试前，游戏退出时备份对应角色存档并记录校验值。普通 Lua 异常可捕获并显示；原生崩溃无法靠 pcall 保证恢复。若跨帧与自动保存可能留下部分状态，必须先验证事务与恢复策略，不能声称绝对原子。

不覆盖原有配装，不自动删装备腾空间，不绕过游戏合法性检查，不修改别人的数据。不承诺复制游戏本身不接受的异常配置。
